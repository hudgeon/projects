# Projects

A private overview of the owner's repositories across their connected machines, with Mark done, optional inboxes, and master conversations that delegate native Claude Code and Codex work to those machines. Today is where people work, on phone and desktop: keep it minimal and plain.

- TanStack Router and Query SPA; TypeScript Worker; SQLite Durable Objects per portfolio owner and per conversation.
- `src/model.ts` owns the snapshot contract and health meanings. `collector/collect.ts` owns native source reads. Never infer clean/complete from a failed, truncated or stale observation.
- Machines join from the site (`worker/machines.ts`): the owner names one and gets its collector and runner tokens once; only hashes are kept, and the owner orders them. Each collector publishes its machine's snapshot every two minutes. The first machine in order heard from in the last five minutes holds the duties: inboxes, Mark done, inbox actions.
- Codex unarchived task != running task or open app window. Claude process != current turn. Preserve evidence and coverage labels.
- Source project progress from canonical plans and GitHub. Do not invent progress percentages or create a second backlog.
- OTP sign-in through Cloudflare Email Service (the `EMAIL` binding) for `ALLOWED_EMAILS` only: one-use codes, attempt limits, revocable secure cookies, the allowlist re-checked per request. Each allowed address is a person (`worker/people.ts`) with own conversations, notifications and inbox; `OWNER_EMAIL` must be allowed (Deploy checks); removing an address ends access, keeping profile and attributions. Collector tokens only upload their machine's snapshot and exchange Mark done and inbox requests; runner tokens only claim, heartbeat and report, and deliver a committed HTML page the owner opened (`worker/documents.ts`, under `DOCUMENT_CSP` from `src/document-model.ts`, never the app's origin). Neither reads the overview. A machine in the deployment's `BROWSER_SIGN_IN` gets each conversation browser signed in (`worker/browser.ts`) as the conversation's owner while their address is allowed: a per-browser, hash-kept, restricted session ending with the browser; no runner route returns it. The claim (`worker/claims.ts`) hands the runner the owner's name and email for prompts, commit authorship and the email lane, never telemetry or snapshots. No auth bypass in production.
- Work items are GitHub issues labelled `work` in each machine's configured `workRepo`: type is the kind, milestone the initiative, `customer:`/`repo:` labels the rest. Every machine with a `workRepo` reads them each scan and caches a copy for its offline hooks; the overview uses the newest successful read. No catalog or note markers.
- Mark done and inbox linking queue only issue/thread IDs; the Worker holds no GitHub credential. The machine on duty closes work or adds the exact email link with its signed-in `gh`; any App token stays read-only. Linking never marks a message reviewed. Inbox Archive/Unsubscribe/link are requests only the inbox's owner makes (`worker/inbox.ts`), applied with that account's `gws` sign-in on the machine on duty; one-click unsubscribe only to public HTTPS hosts. Done on an activity never archives email.
- Each person's inbox is read as them: by delegation (an `inboxAccounts` entry with the address alone; an hour's Gmail token per read or turn, minted in `collector/delegation.ts` from the Workspace service account key `GMAIL_DELEGATION_KEY` in the machine's Doppler config, which never enters `machine.json`, snapshots, logs or prompts) or with their own `gws` sign-in listed with its config directory (`collector/config.ts`; the installer's `--add-inbox`/`--remove-inbox`), and refused when the profile is anyone else's. Only the latest message's bounded plain text leaves Gmail, served to its owner one thread at a time; everyone else sees counts and work-issue links; never in the overview, telemetry or prompts. A conversation's native turns run `gws` as its owner's connected mailbox (sign-in or delegated token), or with no sign-in.
- Push notifications go to the conversation owner's devices, carry no payload and go only to browser push services; devices fetch the notice with their own session.
- Deployment identity is configuration: repository variables that Deploy writes into `wrangler.jsonc` (which holds placeholders), and each machine's `machine.json`. Code, tests, docs and agent-facing prompts name no owner, organisation, domain, repository, machine or connected tool; forks follow docs/self-host.md.
- Runtime secrets stay in Doppler; never store transcripts, tool outputs, credentials or diffs in snapshots.
- `src/run-text.ts` owns how agent text is shown (titles, status lines, documents); it only removes protocol residue and never invents progress or verification.
- `collector/friction*.ts` derives friction from native transcripts by fixed local rules. Receipts (counts, versions, cwd, session ids) stay in the machine's state directory; snapshots carry only per-day totals by app and the versions seen. Never let transcript text, commands, paths or output into a field that leaves the machine.
- The `upkeep` lane (`worker/upkeep.ts`, docs/upkeep.md): the Worker's weekly cron, or Run upkeep now in Settings, starts one conversation for the deployment owner, idempotent per ISO week, linked to the open work issue labelled `upkeep`; each runner keeps it one slot of its own. `runner/upkeep-instructions.ts` is its brief: evidence first, one guarded change a cycle, `configRepo` in machine.json for shared rules, skills and hooks, and edits to global rules or any AGENTS.md end blocked for the owner's review.
- `src/telemetry.ts` owns safe logging/receipt fields; `worker/telemetry.ts` owns Cloudflare spans. Keep prompts, native output, paths and raw exceptions out of telemetry. Preserve correlation IDs and sampling labels; logs never prove execution success.
- Conversations own separate SQLite Durable Objects. New ones go to the first machine in order whose runner called in the last two minutes, and each machine's runner IDs map to owners of its own. A conversation stays on the machine that first claimed it. The collector gains no execution access. `runner/` owns native dispatch and private local journals. Never reassign stale claims or replay uncertain writes; recovery verifies process exit and workspace ownership, then inspects the same native session read-only; recoverable failures reach the master before the owner. The exception is Continue on another machine while the conversation's machine is away: the claim is released, never replayed, and the next claimant starts a new coordinator from the history. Changes use owned worktrees from current origin/main; the master is read-only.
- A change to Jev project review's retrieval, question wording, request shape, 0.5 cutoff or pinned model carries before/after metrics from `npm run context:replay` in its PR (docs/context-selection.md).
- Check `npm run typecheck`, `npm test`, `npm run build`, `npm run collector:build`, `npm run file-sizes:check`, `npm audit --audit-level=high`. Preview ports 5278/8798.
- Project names and canonical plan links belong in repository-local `.project-overview.json`; identity must survive path moves. See public/agents.md. Snapshot replacement removes moved/deleted entries without deleting native sessions.
- Production release: reviewed PR and CI (plus the security review when `.github/release-policy.json` requires it), then manual Deploy on main with project-scoped Doppler OIDC. Runtime secrets stay limited to secrets.required.
- This code is public: after each verified Deploy, `node scripts/publish-public.mjs` copies main's tree, less the security-review gate files (synced from elsewhere), to the `public` remote as one commit. It needs `publish.name`/`publish.email` in Git config and the untracked `.git/info/public-deny` list, refusing while a listed term appears; a checkout without them leaves publishing to one that has them. Keep customer names, real contacts, credentials and other private data out of every file, tests included.
- When a release changes the collector or runner bundles, run `node scripts/install-machine.mjs` from a checkout of the released commit on each connected machine right after the deploy. It builds the bundles from that checkout, records the commit in `release.json` beside them, keeps the machine's config and tokens, and sends a running runner `SIGUSR2`: it restarts at once while each executor finishes its current step on the old version; a stopped runner is kickstarted. It prints what is installed and whether the runner runs on it; a runner that keeps exiting logs `runner_config_invalid` with the rejected key. The owner's standing approval covers this restart; do not wait for idle. A machine that is away gets the release on return.
