# Projects

A private overview of the owner's repositories across their connected machines, with Mark done, an optional inbox, and master conversations that delegate native Claude Code and Codex work to those machines. Today is where the owner works, on phone and desktop: keep it minimal and plain.

- TanStack Router and Query SPA; TypeScript Worker; SQLite Durable Objects per portfolio owner and per conversation.
- `src/model.ts` owns the snapshot contract and health meanings. `collector/collect.ts` owns native source reads. Never infer clean/complete from a failed, truncated or stale observation.
- Machines join from the site (`worker/machines.ts`): the owner names one and gets its collector and runner tokens once; only hashes are kept, and the owner sets the machines' order. Each machine's collector publishes its own snapshot every two minutes. The first machine in order heard from in the last five minutes holds the duties: inbox, Mark done, inbox actions.
- Codex unarchived task != running task or open app window. Claude process != current turn. Preserve evidence and coverage labels.
- Source project progress from canonical plans and GitHub. Do not invent progress percentages or create a second backlog.
- OTP uses Cloudflare Email Service (the `EMAIL` binding) with allowlisted email, one-use codes, attempt limits and revocable secure cookies. Collector tokens only upload their machine's snapshot and exchange Mark done and inbox requests; runner tokens only claim, heartbeat and report, and deliver a committed HTML page the owner opened (`worker/documents.ts`; served under `DOCUMENT_CSP` from `src/document-model.ts`, never with the app's origin). Neither reads the overview. A machine in the deployment's `BROWSER_SIGN_IN` gets each conversation browser signed in by the Worker (`worker/browser.ts`): a per-browser, hash-kept, restricted owner session that ends with the browser; no runner route returns it. No auth bypass in production.
- Work items are GitHub issues labelled `work` in each machine's configured `workRepo`: type is the kind, milestone the initiative, `customer:`/`repo:` labels the rest. Every machine with a `workRepo` reads them each scan and caches its own copy for its offline hooks; the overview uses the newest successful read. No catalog or note markers.
- Mark done and inbox linking queue only issue/thread IDs; the Worker holds no GitHub credential. The machine on duty closes work or adds the exact email link with its signed-in GitHub CLI; any App token stays read-only. Linking never marks a message reviewed. Inbox Archive/Unsubscribe use that machine's `gws` login; one-click unsubscribe only to public HTTPS hosts. Done on an activity never archives email.
- Only the latest inbox message's bounded plain text leaves Gmail, served one thread at a time; never in the overview, telemetry or prompts.
- Push notifications carry no payload and go only to browser push services; devices fetch the notice with their own session.
- Deployment identity is configuration: repository variables that Deploy writes into `wrangler.jsonc` (which holds placeholders), and each machine's `machine.json`. Code, tests, docs and agent-facing prompts name no owner, organisation, domain, repository, machine or connected tool; forks follow docs/self-host.md.
- Runtime secrets stay in Doppler; never store transcripts, tool outputs, credentials or diffs in snapshots.
- `src/run-text.ts` owns how agent text is shown (titles, status lines, documents); it only removes protocol residue and never invents progress or verification.
- `src/telemetry.ts` owns safe logging/receipt fields; `worker/telemetry.ts` owns Cloudflare spans. Keep prompts, native output, paths and raw exceptions out of telemetry. Preserve correlation IDs and sampling labels; logs never prove execution success.
- Conversations own separate SQLite Durable Objects. New ones go to the first machine in order whose runner called in the last two minutes, and each machine's runner IDs map to owners of its own. A conversation stays on the machine that first claimed it. The collector gains no execution access. `runner/` owns native dispatch and private local journals. Never reassign stale claims or replay uncertain writes; recovery verifies process exit and workspace ownership, then inspects the same native session read-only; recoverable failures go back to the master before the owner hears. The one exception is the owner's explicit Continue on another machine while the conversation's machine is away: it releases that claim without replaying it, and the next machine to claim it starts a new coordinator from the conversation's history. Changes use owned worktrees from current origin/main; the master is read-only.
- Check `npm run typecheck`, `npm test`, `npm run build`, `npm run collector:build`, `npm run file-sizes:check`, `npm audit --audit-level=high`. Preview ports 5278/8798.
- Project names and canonical plan links belong in repository-local `.project-overview.json`; identity must survive path moves. See public/agents.md. Snapshot replacement removes moved/deleted entries without deleting native sessions.
- Production release: reviewed PR and CI (plus the security review when `.github/release-policy.json` requires it), then manual Deploy on main using project-scoped Doppler OIDC. Keep runtime secrets limited to secrets.required.
- This code is public: after each verified Deploy, `node scripts/publish-public.mjs` copies main's tree, less the security-review gate files (synced from elsewhere), to the checkout's `public` remote as one commit. It needs `publish.name` and `publish.email` in Git config and the untracked `.git/info/public-deny` list, and refuses while a listed term appears; a checkout without them leaves publishing to one that has them. Keep customer names, real contacts, credentials and other private data out of every file, tests included.
- When a release changes the collector or runner bundles, run `node scripts/install-machine.mjs` on each connected machine right after the Worker deploy; it keeps that machine's config and tokens and sends its runner `SIGUSR2`, which restarts it at once while each conversation's executor finishes its current step on the old version, so no turn is cut short. The repository owner's standing approval covers this restart; do not wait for idle. A machine that is away gets the release when it returns.
