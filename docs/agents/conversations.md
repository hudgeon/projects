# Conversations and the upkeep lane

Facts for agents working on `runner/`, conversation Durable Objects or `worker/upkeep.ts`. `AGENTS.md` holds the invariants that apply everywhere.

- Conversations own separate SQLite Durable Objects. New ones go to the first machine in order with a fresh capacity offer for that lane, and each machine's runner IDs map to owners of its own. A conversation stays on the machine that first claimed it. The collector gains no execution access. `runner/` owns native dispatch and private local journals. Never reassign stale claims or replay uncertain writes; recovery verifies process exit and workspace ownership, then inspects the same native session read-only; recoverable failures reach the master before the owner. The exception is Continue on another machine while the conversation's machine is away: the claim is released, never replayed, and the next claimant starts a new coordinator from the history. Changes use owned worktrees from current origin/main; the master is read-only.
- The deployment owner can choose **Options → Investigate** and select a repository. The runner supplies bounded excerpts from tracked repository files and the linked work item, plus the owner's text and screenshots. One restricted Claude Code session answers directly with cited findings and the first unverified stage. It has no shell, browser, mailbox, connectors or helper agents. The source collection time and individual evidence dates are separate. Follow-ups stay in the original session on its machine. Standard remains the default. Investigations are visible only to their owner and require a compatible runner for first claims and recovery.
- The `upkeep` lane (`worker/upkeep.ts`, docs/upkeep.md): the Worker's weekly cron, or Run upkeep now in Settings, starts one conversation for the deployment owner, idempotent per ISO week, linked to the open work issue labelled `upkeep`; it shares each runner’s capacity and memory-pressure admission with other conversations. `runner/upkeep-instructions.ts` is its brief: evidence first, one guarded change a cycle, `configRepo` in machine.json for shared rules, skills and hooks, and edits to global rules or any AGENTS.md end blocked for the owner's review. Its harness research is one Claude read child given `WebFetch` by domain rules for the official sources in `UPKEEP_SOURCES` (`src/upkeep-model.ts`) and told to read nothing else; proposals are not instructions, and the versions reviewed are the `Reviewed versions:` line under `## Upkeep` in the standing issue. The table of changes beside it is what the next cycle compares (`runner/upkeep-changes.ts`): a change whose measure did not move is revised once or reverted, and a kept change's guard stays.
