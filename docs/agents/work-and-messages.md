# Work items, inboxes, chats and shared support

Facts for agents working on work items, inboxes, `collector/delegation.ts`, `worker/chats.ts`, `collector/chats.ts` or the support source. `AGENTS.md` holds the invariants that apply everywhere.

- Work items are GitHub issues labelled `work` in each machine's configured `workRepo`: type is the kind, milestone the initiative, `customer:`/`repo:` labels the rest. Every machine with a `workRepo` reads them each scan and caches a copy for its offline hooks; the overview uses the newest successful read. No catalog or note markers.
- Each person's inbox is read as them: by delegation (an `inboxAccounts` entry with the address alone; an hour's Gmail token per read or turn, minted in `collector/delegation.ts` from the Workspace service account key `GMAIL_DELEGATION_KEY` in the machine's Doppler config, which never enters `machine.json`, snapshots, logs or prompts) or with their own `gws` sign-in listed with its config directory (`collector/config.ts`; the installer's `--add-inbox`/`--remove-inbox`), and refused when the profile is anyone else's. Only the latest message's bounded plain text leaves Gmail, served to its owner one thread at a time; everyone else sees counts and work-issue links; never in the overview, telemetry or prompts. A conversation's native turns run `gws` as its owner's connected mailbox (sign-in or delegated token), or with no sign-in.
- Slack and Teams items are each person's own (`worker/chats.ts`): a machine posts a read made with that person's own sign-in (Slack: the chat watcher, `collector/chats.ts`, over Socket Mode with their user token; Teams: the same watcher reading a signed-in Chrome profile's chat list over the DevTools protocol, `collector/teams-chrome.ts`, never opening a chat so never sending a read receipt), and the newest per source and person wins. Lists carry a 140-character preview; the latest message's text goes to whoever holds the item, one at a time; none reaches the overview, snapshots, telemetry or prompts. Done and Hand over are kept by the Worker; nothing is posted, marked read or changed in Slack or Teams, and chat credentials stay on the reading machine.
- Shared support is an opt-in message source (`support` in machine.json), visible to its named owner or an explicit handover recipient; it is not a person or another person's inbox grant. A dedicated tool-free, non-persistent classifier receives only bounded incoming text. Initial replies are drafts in that mailbox, explicitly enabled and reserved durably before creation; no automatic send, overwrite or deletion. Uncertain creation is reconciled against the exact draft and never replayed. A draft never counts as delivery, human response or resolution. See docs/support-email.md.
